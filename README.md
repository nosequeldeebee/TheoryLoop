# TheoryLoop

**A planted-mechanism benchmark and LLM test for AI theory-building loops.**

Coding agents work in loops with every pass being checked by
the compiler and test suite. Social science has no compiler, so a
theory-building loop has nothing to stop it from confidently converging on
nonsense. `TheoryLoop` supplies the missing pieces:

1. **Worlds with known truth.** Synthetic NFT (non-fungible token) data where a "legitimacy"
   core is generated by a mechanism we planted. Because we wrote the
   mechanism, we can score any theory a loop produces against it.
2. **Theory as code.** A theory is a list of testable propositions
   (NFT example: "the presence of a verification badge raises legitimacy when launched in a bear market"). 
   Loops can be run on two halves of the data where the loops don't see each other: one that generates these claims (discovery), 
   and another that tests them (holdout).
3. **Subagent roles with separate contexts.** A *proposer* drafts claims, a
   *falsifier* tries to break them (with controls, moderators, failures), a *reviser*
   applies the objections. The loop runs until the falsifier finds nothing.
4. **A ledger of every test.** Loops multiply forking paths. Every test any
   agent runs is logged, so the number of tests behind each claim is visible.

## Quick start

Requires Go 1.24 or later. 

```bash
go test ./...                                   # 15 tests, no API key needed
go run ./cmd/theoryloop bench                   # code-based reference subagents: 5 worlds x 500 seeds x 3 conditions (see below) (~10 s)
go run ./cmd/theoryloop export                  # write the generated datasets to data/ as CSV

export ANTHROPIC_API_KEY=...
go run ./cmd/theoryloop bench -backend llm -seeds 10              # Claude subagents
go run ./cmd/theoryloop bench -backend llm -seeds 10 -anonymize   # same, variable names hidden to hide context from Claude
```

To run the LLM backend without an API key, add `-replay DIR`. Each model call is
then written to `DIR/pending/<id>.txt` and the run waits for a reply in
`DIR/replies/<id>.txt`; rerun `bench` after supplying replies until nothing is
pending. `results/llm_pilot_4seeds_v1/` (original prompt, 4 datasets per world), `results/llm_pilot_4seeds_v2/` (proposer may answer "nothing supported", 4 per world) and `results/llm_pilot_20seeds/` (same prompt as v2, 20 per world) and `results/llm_pilot_20seeds_anonymized/` (the same with variables hidden). We ran the LLM tests this way, with
every prompt and reply kept.

Or build a single binary with `go build -o theoryloop ./cmd/theoryloop`.

Useful `bench` flags: `-worlds confound,null` to run a subset, `-model` to choose
the model, `-workers` for parallel runs (default 4 for the LLM backend, which
retries rate-limit erros with backoff). A run whose model call fails is
recorded with its error and excluded from the summary, rather than stopping the run.

## Data

There are no input files: each world is generated from its seed by `MakeWorld`
in `worlds.go`. `data/` holds the
first three seeds of every world, exported with `theoryloop export`, so the data
can be inspected separately and without running Go. Each CSV file marks every
row as `discovery` or `holdout`; `data/truth.json` lists the planted mechanisms.

| world | planted mechanism | failure mode it probes |
|---|---|---|
| `main` | verification raises legitimacy | finding a simple mechanism among distractors |
| `scope` | verification matters only in bear-market launches | missing boundary conditions |
| `confound` | community size drives both verification and legitimacy | decoy correlations |
| `null` | nothing | false theory from noise |
| `multi` | wash trading above 30% destroys legitimacy; creator reputation helps | multiple mechanisms, nonlinearity |

## Conditions 

- `single_pass`: proposer only, no falsifier 
- `loop`: proposer → falsifier → reviser, repeated until no objections
- `loop_holdout`: loop, then every surviving claim (including each scope condition) must also work on held-out cases

## Results 

### Reference (code-based) agent results:

| condition | recovered planted theory exactly | asserted a non-existent mechanism |
|---|---|---|
| single pass | 37% | 50% |
| adversarial loop | 60% | 37% |
| loop + holdout gate | 93% | 3% |

### LLM (Claude) agent results:

| condition | named variables:<br>recovered planted theory exactly / asserted a non-existent mechanism | anonymized variables:<br>recovered planted theory exactly / asserted a non-existent mechanism |
|---|---|---|
| single pass | 59% / 22% | 59% / 21% | 
| adversarial loop | 92% / 2% | 94% / 1% | 
| loop + holdout gate | 98% / 0% | 98% / 0% | 

Full tables: `results/heuristic_summary.md`; every run: `results/heuristic_runs.csv`;
per-step ledgers for the first three seeds of each cell: `results/heuristic_ledgers/`. LLM results
are in the corresponding subfolders in `results`

The reference subagents are deterministic rules, not the object of study. They
validate the workflow and set the benchmark. The research question is how LLM subagents
compare, and whether they find theory in the data or in their priors (the
`-anonymize` contrast).

## Layout of this Repository

```
worlds.go             planted-mechanism data generators and truth sets
theory.go             propositions as executable claims
stats.go              random draws, OLS, t-distribution p-values using the Go standard library 
agents.go             proposer / falsifier / reviser; code-based/heuristic backend
llm.go                Claude backend: API client, prompts, anonymization
loop.go               the loop, holdout gate, scoring against truth
ledger.go             log of every test run
data.go               column-oriented data, discovery/holdout split
theoryloop_test.go    tests
cmd/theoryloop/       command-line tool: bench, export
docs/technical_appendix.md
```
